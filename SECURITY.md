# Security policy

## Supported versions

WorkCrate is pre-1.0. Security fixes are developed on **`dev`** and included in the next **`dev` → `main`** release (tag on **`main`**).

| Version / branch | Supported |
|------------------|-----------|
| Latest tag on **`main`** | Yes |
| **`main`** (at a release tag) | Yes |
| **`dev`** | Yes (integration; not a published release line) |
| Older tags | Best effort |

## Reporting a vulnerability

**Do not** report security vulnerabilities in public GitHub issues.

Use **[GitHub private vulnerability reporting](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing-information-about-vulnerabilities/privately-reporting-a-security-vulnerability)** for this repository (Security tab → Report a vulnerability).

Include:

- Description and impact
- Steps to reproduce
- Affected component (backend, frontend, scripts, docs)
- Version or commit if known

## Response

Maintainers will acknowledge reports on a best-effort basis. We do not guarantee a fixed timeline or SLA while the project is in early development.

## Safe harbor

We support good-faith security research that follows this policy and avoids privacy violations, data destruction, or service disruption.
